# libSceIcu technical debt

### Functional

- [Invariant character handling](../../../core/libs/prx/libSceIcu/Invariant.cpp): the console ICU version, charset build setting and debug assertions remain unverified. These exports follow release ASCII-family [ICU 78.1 uinvchar.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/uinvchar.cpp). Byte widening zero-extends all input bytes. Unicode narrowing emits NUL for non-invariant units, as the reference does with U_DEBUG disabled. Counted predicates include embedded NULs; any negative predicate length means NUL-terminated input. Nonpositive widening/narrowing counts read neither pointer. The EBCDIC copy requires a valid source even for nonpositive counts; -1 includes the source terminator, and other positive counts pad to that size. Caller storage and pointer preconditions follow the reference; no console comparison has been run.

- [Invariant EBCDIC and property-name helpers](../../../core/libs/prx/libSceIcu/Invariant.cpp): exact console maps and comparison results remain unverified. ICU's maps are invariant-character helpers, not complete code-page converters. The separate lowercase table retains its source distinction at byte E0, which maps to ASCII vertical bar instead of backslash. Property comparison follows [propname.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/propname.cpp) and its charset-specific case and separator rules. EBCDIC properties compare EBCDIC values after case folding; the invariant comparison separately maps invariant bytes into ASCII order and orders other unequal bytes by their negative unsigned values. Inputs must satisfy the reference's readable NUL-terminated string preconditions.
