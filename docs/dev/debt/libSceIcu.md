# libSceIcu technical debt

### Functional

- [UTF-8 safe macro bodies](../../../core/libs/prx/libSceIcu/Utf8.cpp): PS5 ICU version, signatures and console equivalence remain unverified. The four names/NIDs are in the [PS5 3.20 inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceIcu.c); behavior follows ICU 78.1 [utf_impl.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/utf_impl.cpp). These are macro bodies, including length-matched legacy error values and two-byte direct ASCII append, rather than complete character-encoding APIs. Invalid buffers, missing required pointers and indexes whose source arithmetic or memory access is undefined throw when detectable; other invalid storage remains a caller error.

- [Public iterator comparison and UText traversal](../../../core/libs/prx/libSceIcu/GuestText.hpp): console ABI and ICU version compatibility are not measured. The inventory records names and NIDs, while ICU 78.1 public [uiter.h](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/unicode/uiter.h) and [utext.h](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/unicode/utext.h) define the 112-byte UCharIterator, 112-byte UTextFuncs and 144-byte UText layouts used here. Provider callbacks use the guest System V ABI; arbitrary valid callback implementations are supported without interpreting provider context or restricting callback identities.

- [UText source edge cases](../../../core/libs/prx/libSceIcu/TextTraversal.cpp): exact PS5 behavior for wide native spans and invalid provider responses is unknown. Internal index restoration retains [utext.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/utext.cpp)'s signed-32-bit narrowing before comparing nativeIndexingLimit, including defined wraparound cases. Providers reporting successful access without an addressable chunk, invalid offsets and missing required callbacks throw before invalid reads. A native ICU UTF-8 provider can return success with an empty chunk when seeking backward inside the first multibyte sequence; the original traversal then decrements offset below zero and reads outside the buffer. That source-undefined read is rejected generically rather than replaced with a guessed code point. Valid end-of-text/start-of-text failures retain the source's U_SENTINEL result.
