# libSceIcu technical debt

### Unknown function info

- [ICU export availability](../../../core/libs/prx/libSceIcu/Unescape.cpp) across firmware versions remains unproven. The [PS5 3.20 inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceIcu.c) includes the implemented escape, invariant-character and version helpers. [BunnyFl’s firmware 13.42 report](https://github.com/boykopovar/AnyPS5/pull/10961#issuecomment-6400071863) records `u_getVersion` returning `78.1.0.0` under an emulator, but neither escape function is in the checked native `system_ex/common_ex/lib/libSceIcu.sprx` export table. Only 104 of the 661 inventory NIDs appear among that module’s 299 exports. The exports for compatibility with older firmware are retained; availability and routing across firmware versions remain unproven.

### Functional

- [Escape decoding](../../../core/libs/prx/libSceIcu/Unescape.cpp) has no behavior or ABI verification on console hardware. It follows ICU 78.1's [ustring.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustring.cpp), including rejection of eight-digit braced hexadecimal escapes although its public header advertises up to eight digits. Null source or offset pointers, null callbacks with an in-range offset, negative capacity with a nonnull destination and source lengths exceeding `INT32_MAX` throw. Null-destination preflight ignores capacity. Closes when: compared with the console, including callback ABI, byte conversion, capacity limits and braced hexadecimal parsing.

- [Invariant character and version helpers](../../../core/libs/prx/libSceIcu/Version.cpp) are unverified on a console. `u_charsToUChars`, `u_UCharsToChars`, `u_versionFromString`, `u_versionFromUString` and `u_versionToString` follow ICU 78.1 [uinvchar.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/uinvchar.cpp) and [putil.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/putil.cpp), unchanged since 65.1. Firmware 13.42 reports ICU 78.1 and exports none of them ([#11013](https://github.com/boykopovar/AnyPS5/pull/11013#issuecomment-6400470698)); the [3.20 table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceIcu.c) has all five. Version parts use the guest `strtoul`, truncated to eight bits; `u_versionToString` keeps ICU's dropped zero tens digit (105 becomes `15`). A null buffer with a positive conversion length throws; ICU dereferences it. Closes when: compared with the console.

- [UTF-16 set searches and tokenization](../../../core/libs/prx/libSceIcu/Tokenize.cpp) have no console verification; ICU versions on other firmware are unverified. Signatures and behavior follow ICU 78.1's [ustring.h](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/unicode/ustring.h) and [ustring.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustring.cpp). `u_strtok_r` preserves that source's one-code-unit delimiter overwrite, including the trailing surrogate left after splitting at a supplementary delimiter. Invalid null inputs and rejected guest-write scopes throw; an initial continuation assignment is retained if a later delimiter write is rejected. Set-search offsets beyond `INT32_MAX` throw; other unimplemented library exports remain absent.

- [UTF-16 lexical comparisons](../../../core/libs/prx/libSceIcu/Comparisons.cpp): equivalence on console hardware remains unverified. The five exports follow [ICU 78.1 ustring.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustring.cpp) and its public UTF-16 ABI. Required null buffers throw where upstream dereferences them; nonpositive `u_strncmp`/`u_memcmp` counts and a zero code-point comparison count or identical code-point buffers read nothing. Negative `u_memcmpCodePointOrder` counts select NUL-terminated lengths, preserving the first differing code-unit result. Strings whose length cannot fit int32 throw instead of narrowing the length.

- [Firmware availability](../../../core/libs/prx/libSceIcu/Comparisons.cpp): [BunnyFl’s firmware 13.42 report](https://github.com/boykopovar/AnyPS5/pull/10963#issuecomment-6400072356) records `u_getVersion` returning `78.1.0.0` with `system_ex/common_ex/lib/libSceIcu.sprx` run under an emulator. None of these five lexical APIs is in that native module’s 299 exports. The 3.20 compatibility exports are retained; availability and routing across firmware versions remain unproven.

- [UTF-16 copying](../../../core/libs/prx/libSceIcu/Copy.cpp): the console ICU version and exact copy/concatenation behavior are unverified. These five exports follow [ICU 78.1 ustring.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustring.cpp): `u_strncpy` stops at the first copied NUL without padding, and `u_strncat` appends up to the positive count of code units followed by NUL. The latter follows the implementation, despite its header's conflicting count-minus-one prose. Nonpositive counts leave the destination untouched, without reading either pointer. Code units, including unpaired surrogates, are copied without Unicode validation. As in the reference, callers supply sufficient storage and valid nonoverlapping ranges; invalid positive-count pointers and overlapping `u_memcpy` are outside its contract.

- [Guest copy access](../../../core/libs/prx/libSceIcu/Copy.cpp): console behavior for invalid null buffers or rejected host-write access is unknown; these inputs throw. Destination guards cover the actual copied units and terminator, without opening unused capacity or the read-only prefix of a concatenation. Mapping writability and write-watch support follow the platform GuestArena backend.

- [UTF-8 and UTF-16 conversions](../../../core/libs/prx/libSceIcu/UtfConversions.cpp): exact PS5 version equivalence is unverified. The five conversion exports follow ICU 78.1 [ustrtrns.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustrtrns.cpp), including strict/substitution handling, lenient malformed-byte output, error preservation and buffer termination. A null error pointer and lengths whose result cannot fit the signed 32-bit ICU API throw; ICU requires a valid error pointer and does not define useful overflow behavior there. Source and destination must not overlap, as required by ICU. A refused guest output write guard throws before modifying any output; ICU does not specify a guest memory access error for invalid output mappings.

- [UTF-16 scalar counting and search](../../../core/libs/prx/libSceIcu/Utf16.cpp): equivalence on console hardware is not established beyond the firmware 13.42 emulator cases below. The five APIs follow the stable public contracts and implementation of ICU 78.1 [ustring.h](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/unicode/ustring.h) and [ustring.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustring.cpp), including isolated-surrogate matches, counted embedded NULs, truncated pairs and invalid scalar rejection. Null search inputs that require a read and terminated counts beyond INT32_MAX throw; the public API does not define such valid inputs. Invalid buffers and overlapping concurrent modification remain caller errors.

- [UTF-16 scalar ABI](../../../core/libs/prx/libSceIcu/Utf16.cpp): argument and return type compatibility on console hardware remains unmeasured. Export names and NIDs are in the [PS5 3.20 inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceIcu.c). The adapter uses public ICU UChar as a 16-bit unit, UChar32 and lengths as signed 32 bits, UBool as signed 8 bits, and guest System V calling conventions; the inventory alone does not establish these types.

- [Firmware availability and conformance](../../../core/libs/prx/libSceIcu/Utf16.cpp): [BunnyFl’s firmware 13.42 report](https://github.com/boykopovar/AnyPS5/pull/10966#issuecomment-6400072800) records `u_getVersion` returning `78.1.0.0` with `system_ex/common_ex/lib/libSceIcu.sprx` run under an emulator. `u_countChar32` matched 94,111 bounded cases covering mapping ends, null text, negative and explicit lengths, NULs and surrogates. `u_strHasMoreChar32Than`, `u_strchr32`, `u_strrchr32` and `u_memchr32` are absent from that module’s exports. The 3.20 compatibility exports are retained; hardware equivalence and availability/routing across firmware versions remain unproven.

- [Bulk UTF-16 writes](../../../core/libs/prx/libSceIcu/Search.cpp) throw when `HostWrite` rejects the destination; the console's invalid-destination behavior is unverified. Windows logical read-only guest-view rejection has a runtime regression but has not been executed locally on Windows. Linux does not reject read-only views through this guard; a positive write to such a view still faults.

- [UTF-16 search, comparison and memory helpers](../../../core/libs/prx/libSceIcu/Search.cpp) have no console verification. Their public signatures and behavior follow ICU 78.1's [ustring.h](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/unicode/ustring.h) and [ustring.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustring.cpp). Undefined null reads and writes throw; defined null and zero-count shortcuts remain available. Search paths that measure a 32-bit length throw if it exceeds `INT32_MAX`, instead of narrowing it; streaming reference paths retain their early returns.
